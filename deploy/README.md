# Деплой

## Сейчас: локально, через Docker Compose

Две собираемые части:
- `backend/Dockerfile` — FastAPI-приложение (все 4 солвера, включая
  вендоренные бинарники CPLEX/ALGLIB/QORE из `backend/engines/` и отдельный
  интерпретатор CPython 3.8 для QORE).
- `frontend/Dockerfile` — многостадийная сборка: `npm run build`, затем
  готовые статические файлы отдаются через `nginx`, который же проксирует
  API-запросы на `backend` и (если задан домен) сам получает/продлевает
  TLS-сертификат через certbot — см. `deploy/nginx/`.

Запуск:
```
cp .env.example .env   # заполнить реальный пароль админа
docker compose up --build
```
По умолчанию (без доп. файла) — **без GPU**: cuOpt/CUDA вообще не
устанавливаются при сборке (это многогигабайтная CUDA/RAPIDS-цепочка,
которая нужна только cuOpt — CPLEX/ALGLIB/QORE её не трогают), cuOpt в
`/solvers` будет показан недоступным, остальные три солвера работают как
обычно. Подходит для стенда без карты.

Если на хосте есть GPU и установлен `nvidia-container-toolkit` — собирайте
с доп. compose-файлом, он включает и установку cuOpt, и проброс карты:
```
docker compose -f docker-compose.yml -f docker-compose.gpu.yml up --build
```

`backend/data/` монтируется с хоста как volume — SQLite-база, загруженные
MPS-файлы, логи и результаты солвов переживают пересоздание контейнера.

## TLS

Управляется одной переменной в `.env` — `DOMAIN`:

- **`DOMAIN` не задан** — nginx поднимается на порту 80, без шифрования.
  При старте контейнер печатает в лог явное предупреждение об этом.
  Подходит только для локальной проверки (`http://localhost`), **не для
  деплоя, доступного из интернета**.
- **`DOMAIN` задан** (домен должен уже указывать на публичный IP этого
  сервера) — nginx при первом запуске сам получает сертификат Let's
  Encrypt через `certbot` (webroot-метод, HTTP-01 challenge), дальше
  отдаёт сайт по HTTPS на 443 и продлевает сертификат в фоне каждые 12
  часов. Нужен ещё `CERTBOT_EMAIL` (контактный email для Let's Encrypt).
  Сертификаты лежат в `./deploy/letsencrypt` (смонтировано volume'ом,
  переживает пересоздание контейнера — не должно перезапрашиваться при
  каждом деплое, у Let's Encrypt есть лимиты на количество выдач).

Логика — `deploy/nginx/entrypoint.sh`: решает, какой из трёх конфигов
взять (`http.conf` / `bootstrap.conf.template` на время первичной выдачи
сертификата / `https.conf.template` после).

Не забудьте так же выставить `SOLVER_SERVER_SESSION_COOKIE_SECURE=true` в
`.env`, когда включаете `DOMAIN` — иначе cookie сессии не помечается
`Secure` даже при работающем HTTPS.

## Вендоренные бинарники солверов (не в git)

`backend/engines/**/*.so`/`*.dll`/`*.h` (CPLEX/ALGLIB/QORE) не хранятся в
git (см. корневой `.gitignore`) — доставляются на сервер отдельно:
- `./deploy/pack-engines.sh` (запускать из корня репозитория, локально) —
  собирает `engines-binaries.tar.gz` из всех `.so`/`.dll`/`.h` под
  `backend/engines/`.
- `scp engines-binaries.tar.gz <user>@<host>:~/` — отправить на сервер.
- `bash unpack-engines.sh ~/engines-binaries.tar.gz ~/solver_arena` (на
  сервере, из `deploy/` склонированного репозитория) — распаковывает
  обратно по местам и удаляет архив.

Миграции БД гоняются автоматически при старте приложения (см.
`app/main.py`), отдельный шаг для этого не нужен.
